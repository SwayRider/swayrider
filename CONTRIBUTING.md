# CONTRIBUTING.md – SwayRider

## 1. Welcome

Thank you for contributing to the SwayRider Ecosystem.

By contributing, you help improve a modular software ecosystem covering backend, frontend, mobile, infrastructure, and supporting services.

## 2. Legal Requirements (CLA + DCO)

All contributions to SwayRider are subject to two requirements:

- **Contributor License Agreement (CLA) acceptance**
- **Developer Certificate of Origin (DCO) sign-off**

Both are mandatory before any contribution can be merged.

## 3. Contributor License Agreement (CLA)

### 3. 1 Requirement

Before your contribution can be accepted, you must accept the applicable CLA:

- Individual Contributor License Agreement (ICLA)
- Corporate Contributor License Agreement (CCLA), if contributing on behalf of a company

Acceptance of the **ICLA** is handled automatically via the CLA Assistant GitHub workflow.

Acceptance of the **CCLA** is a manual procedure. Please send a request to **maarten(at)hevanto(dot)be** to receive a copy of the **CCLA** and return a signed copy.

### 3.2 CLA Scope

The CLA governs:

- ownership of contributions
- licensing rights granted to the Project Steward
- commercial exploitation rights
- sublicensing and relicensing rights
- transferability to affiliated or successor entities

### 3.3 When CLA must be accepted

- Before the first contribution is merged
- If the CLA changes, you may be required to re-accept it

## 4. Developer Certificate of Origin (DCO)

### 4.1 Requirement

All commits must be signed off using the DCO:

```bash
git commit -s
```

This adds the following line to your commit:

```
Signed-off-by: Your Name <your.email@example.com>
```

### 4.2 DCO Statement

By signing off your commits, you certify that:

- You have the right to submit the contribution
- The contribution is your original work or properly licensed
- You are not knowingly violating any third-party rights
- You agree the contribution may be distributed under the SwayRider licensing model (including AGPL and commercial licensing where applicable)

## 5. Relationship Between CLA and DCO

The CLA and DCO serve different purposes:

| **Mechanism** |	**Purpose** |
| ------------- | ----------- |
| CLA	          | Legal licensing and commercial rights grant to Project Steward |
| DCO           | Per-commit certification of origin and rights to submit |

Both are required. One does not replace the other.

## 6. Pull Request Flow

To contribute:

### Step 1 — Fork & branch

Create a feature branch from the repository.

### Step 2 — Sign commits (DCO)

Use:

```bash
git commit -s
```

### Step 3 — Open Pull Request

Submit your PR to the SwayRider repository.

### Step 4 — Accept CLA

- The CLA Assistant bot will automatically comment on your PR
- You must accept the CLA before review or merge can proceed

### Step 5 — CI checks

All automated checks must pass (tests, linting, CLA verification, DCO compliance if enforced).

## 7. Scope of Contributions

Contributions may include (but are not limited to):

- source code (backend, frontend, mobile, infrastructure)
- APIs and protocol definitions
- documentation
- configuration files
- architecture and design proposals
- bug fixes and patches

## 8. Licensing Model Awareness

By contributing, you acknowledge that:

- SwayRider is licensed under AGPL-3.0-or-later at the project level
- Contributions are subject to CLA licensing terms granted to the Project Steward
- The Project Steward may apply dual licensing, including commercial licensing through affiliated entities (e.g., HEVANTO BV or successors)

## 9. Code of Conduct

All contributors are expected to act professionally and respectfully.

Unacceptable behavior includes harassment, discrimination, or disruptive conduct.

Before contributing, ensure:
